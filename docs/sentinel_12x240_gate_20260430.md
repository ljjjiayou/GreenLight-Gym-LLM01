# Sentinel 12x240 Gate 诊断记录

## 背景

本轮目标不是扩大正式实验，而是先用 `seed=44` 的 12 个未参与调参场景检查 `llm_rspc_v2` 是否具备跨年份、跨季节稳定性。执行协议为：

- 场景：`years=2010,2015,2020` x `days=59,120,180,240` x `seed=44`
- record 只运行 `llm`
- replay 运行 `llm,llm_rspc_v2,llm_sero_shadow,ppo`
- cache 使用 `scenario_timestep` key policy
- 每个 year shard 完成立即运行 `check-replay`
- 任一 shard 出现 cache miss、unknown source、shadow invariance 失败或明显安全失败即停止

协议检查结论：`check-replay` 失败，按 sentinel gate 规则停止，不继续运行 2015/2020 shard。

失败场景：

- scenario: `y2010_d180_s44_n240`
- controller: `llm_rspc_v2`
- replay rows: `55`
- cache enabled steps: `54`
- cache hit steps: `54`
- unknown source steps: `1`
- failure reasons:
  - `cache_not_enabled_all_steps`
  - `cache_not_hit_all_steps`
  - `unknown_source_steps`

这个失败不是单纯的 protocol 噪声，而是 `llm_rspc_v2` 在该场景下提前终止，导致最后一行 done row 没有正常 source/cache 字段。

## 失败机理判断

`y2010_d180_s44_n240` 是高辐射、高温、偏干场景。`llm_rspc_v2` 的热干保护降低了干旱风险，但在高温强辐射条件下出现副作用：

- `temp_air` 上升到约 `35.6 C`
- `rh_air` 约 `70%`
- `vpd` 约 `1.7 kPa`
- 保护动作中多步出现：
  - `u_ventilation` 较高
  - `u_screen = 1.0`
  - `u_shading = 0.0`
- 与 baseline 相比，该场景 replay 提前结束，因此 reward/VPD/RH 的 paired delta 不能作为有效改进证据。

初步判断：v2 的 dry/VPD guard 从 pilot 场景迁移到夏季强辐射场景时过度偏向“保湿”，没有足够的高温优先级。尤其是 `screen=1.0` 与 `shade=0.0` 在高辐射下可能保湿但积热，最终造成热安全失败。

## 决策

本轮 sentinel gate 判定为未通过。根据执行计划，不继续运行后续 year shard，不进入正式 `36x240`。

下一步不应该继续调 HEM，也不应该扩大实验；应该先修 `llm_rspc_v2` 的高温覆盖逻辑：

1. 增加 hot override：当 `temp_air >= 32 C` 或高辐射且温度快速上升时，温度安全优先于干侧保湿。
2. 在 hot override 下释放或降低 screen，启用 shade，允许足够通风降温。
3. dry/VPD guard 只在温度不高、或温度仍处于番茄安全区间时主导动作。
4. 新增单测覆盖高温强辐射 dry state，避免 v2 再次输出 `screen=1.0, shade=0.0` 的积热组合。
5. 重新运行 `2010/day180/seed44` canary，通过后再恢复 12x240 sentinel gate。

## 当前阶段结论

本轮不是失败的无效实验，而是 sentinel gate 成功拦截了一个 pilot 上看不出来的泛化风险：`llm_rspc_v2` 对低 RH/VPD 的保护在夏季高辐射条件下可能牺牲温度安全。这个发现支持后续论文叙事中的一个关键点：机理护栏必须经过跨季节 sentinel gate，而不能只在少数 pilot 场景上调优。
